## 實作重點與設計原因

- **1. Client 所有權與例外清理**
  - Caller(呼叫端) 提供工廠與設定；Executor(執行器) 取得 Client(用戶端) 後負責關閉。
  - 工廠呼叫位於 try 前；取得 Client 後，載入主機資料、連線成功或失敗都透過 finally 嘗試關閉。
  - connect 失敗仍可能已取得部分網路資源，不能因未登入成功就略過清理。
  - finally 正常完成不會吞掉原例外；Caller 若未捕捉例外，呼叫下一行不會執行。
  - probe 是伺服器與監控領域的探測用語；本課統一使用 probe_ssh_connection。
- **2. SSH 驗證的兩個方向**
  - SSH（Secure Shell，安全遠端連線協定）中，Client 使用 known_hosts 中的主機公鑰驗證 Server(伺服器)。
  - Client 使用使用者私鑰證明身分，Server 依其授權公鑰資料驗證；不傳送私鑰本身。
  - RejectPolicy 拒絕未知主機，不自動加入信任；已知主機金鑰不符由金鑰比對拒絕，不是 missing-host-key 政策的處理分支。
  - 關閉金鑰自動搜尋與 SSH agent（金鑰代理程式），明確使用 Caller 指定的資料。
- **3. 等待設定與密語來源**
  - timeout 對應 TCP（Transmission Control Protocol，傳輸控制協定）連線等待；banner_timeout 等待 SSH 協定識別字串；auth_timeout 等待身分驗證回應。
  - banner 在這裡是例如 SSH-2.0-OpenSSH_9.6 的協定識別資訊；收到不代表已驗證可信主機或登入成功。
  - 三者各設五秒不代表整體流程最多五秒，也不能直接當作十五秒總期限。
  - 密語由外部供應，匯入與核心函式不互動詢問。
- **4. 現代 Python 與介面契約**
  - 學員希望使用現代 Python；後續優先使用清楚的型別標註、Path 與適合的語法，不為新而增加複雜度。
  - 函式的 * 要求後面的參數具名傳入；dataclass 的 kw_only=True 控制自動產生的初始化參數。
  - Callable[[], T] 表示無參數、回傳 T 的 callable；類別也能作工廠。
  - Python 執行時不自動強制型別標註；獨立 FakeClient 即使可執行，也不一定符合 SSHClient 類別型別。
  - Protocol 描述所需行為，允許符合簽章的真、假 Client 使用相同介面；其中 ... 表示省略實作，不會自動拋出未實作錯誤。
  - **kwargs: object 描述每個值，收集後是 dict[str, object]；標成 dict 會表示每個值本身都是字典。
  - Path 表達檔案路徑，在 Paramiko 邊界轉成 str；建立 Path 不會讀取、建立或確認檔案存在。
- **5. 測試證據與例外驗證**
  - FakeClient 記錄參數、政策與關閉次數；只能驗證 Executor 的使用流程，不證明真實金鑰驗證。
  - try/except/else 可驗證預期例外；沒有例外時必須在 else 主動失敗。
  - 標準函式庫 unittest 也提供例外斷言；pytest.raises 是較簡潔的外部套件寫法。

## 獨立實作的設計重點

- **1. 工廠、介面與 Client 的責任**
  - ConnectClient 的 Protocol 描述介面；FakeClient 實作方法；工廠無參數並提供 Client。
  - Caller 提供設定，Executor 的 verify_ssh_access 接收工廠與設定，不限只能傳類別。
  - 學員能說明工廠在 try 前失敗，不進入 finally；尚未取得 Client，因此 Executor 的 close 次數應為零。
- **2. 契約與資源所有權**
  - 工廠交出本次可用 Client 及關閉責任；成功回傳 None，工作例外在正常清理後傳出。
  - passphrase: str | None 只代表允許 None；加上 = None 才能省略參數，已修正。
  - 本課假設 close 正常；清理與工作同時失敗的政策留 Day 9，不將本課成果視為全面處理。
- **3. 有效測試與觀察點**
  - 檢查 MissingHostKeyPolicy 太寬，AutoAddPolicy 也會符合；要檢查 RejectPolicy 才能保護拒絕未知主機的設定。
  - 類別層級計數器可觀察建構失敗的假類別，測試前重設，避免順序依賴。
  - close 方法仍需 self；未被測試路徑呼叫的方法有錯，四個測試仍可能全綠。
  - 需另確認計數方法本身可用，不能把零次當作觀察點有效的證明。

## 真實 SSH 登入驗收

- 2026-11-09（Asia/Taipei），教師使用 Windows OpenSSH 確認執行中的 VirtualBox 虛擬機 `ServerLab-Ubuntu` 可登入。VirtualBox 將 `127.0.0.1:2222` 轉發至 Ubuntu 的 SSH 連接埠 22。
- 使用既有的 `serverlab_ed25519` 金鑰，啟用嚴格主機金鑰檢查，採公鑰驗證登入。以下指令以已設定課程帳號的環境重現，將 `<帳號>` 換成實際登入帳號。

```powershell
ssh -tt -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=yes -o IdentitiesOnly=yes -o PreferredAuthentications=publickey -i "$env:USERPROFILE\.ssh\serverlab_ed25519" -p 2222 <帳號>@127.0.0.1
```

- 取得 Ubuntu 互動式 shell，`hostname` 回傳 `serverlab-ubuntu`，執行 `exit` 後正常結束，SSH 結束代碼為 `0`。
- 同日，學員在互動式 Python 中親自呼叫 `verify_ssh_access(paramiko.SSHClient, ...)`，傳入相同的主機、連接埠、私鑰及 `known_hosts` 路徑，透過 `getpass()` 取得密語輸入。
- 學員回報 `print(result)` 顯示 `None`，沒有拋出例外，符合實作的成功契約。這次使用真實 Client，走過主機金鑰檢查、使用者驗證及 `finally` 關閉流程。失敗路徑的證據來自假物件測試。
