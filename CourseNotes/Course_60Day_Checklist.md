# 60 天軟體工程實作課程檢查表

專案：Python Server Validation Automation Framework（Python 伺服器驗證自動化框架）。
目標：完成可展示的免費測試執行框架，練習軟體架構、並行、例外處理、資源管理、測試與效能分析，作為 Software Tool Development（軟體工具開發）／Automation Framework Engineer（自動化框架工程師）求職作品。

教材入口：[60 天教材索引](Course_Index.md)。筆記格式：[Note_Template.md](Note_Template.md)。

## 使用方式

- 每個 Day（課程日）約一小時，依完成進度前進，不強制連續 60 個日曆日。
- 第 1 天已完成，對應 [Note_Day1_261030.md](Note_Day1_261030.md)。60 天教材已預備為 `Course_DayN.md`；實際上課後新增 `Note_DayN_YYMMDD.md`，日期依台灣時間填寫。
- 每日新對話建議命名為 `Course_DayN`，開課時請先讀本檢查表與最近一份課程筆記。
- 教學順序：列出當日目標 → 講解觀念、設計原因與取捨 → 提供當日教學範例的完整可執行程式碼、測試及執行方式 → 學員操作與提問 → 完成三題複習並回饋 → 出一題相似但有變化的實作題 → 需求分析與設計討論 → 學員實作 → 測試與 Code Review（程式碼審查）→ 整理筆記並結課。
- 教材已全數預備，正式教學仍逐日進行；完整程式碼以當日範圍為界，說明每個檔案的位置、相依套件、執行步驟與預期結果；逐項解釋為何這樣拆分責任、處理例外與管理資源，以及替代設計的取捨。預備範例不代表專案已實作完成。
- 實作練習在教學與三題複習完成後才出題；出題時說明情境、限制與驗收案例，由學員先分析需求並提出設計。練習解答不預先提供，學員要求時再提供提示或完整解答。
- 每日建議分配：5 分鐘目標與複習、20 分鐘教學與完整範例操作、5 分鐘三題複習、10 分鐘練習需求與設計、15 分鐘實作與審查、5 分鐘筆記。各日內容須縮小到可在約一小時內完成，必要時拆課。
- 完成當日目標就提醒課程結束，不為湊滿一小時追加課程。超時則記錄阻礙與下一步，未達驗收不勾選完成，可拆成下一次繼續。
- 每日完成條件：教學範例已操作並符合預期、三題複習已回饋、一道相似實作練習已完成並通過驗收與審查、筆記已整理。純設計主題提供完整設計示範，以情境走查驗收，不為了形式硬加無關程式碼。
- 每日條目的練習與驗收描述為當日主題範圍；實際上課依上述順序提供教學範例與另一題相似練習，不把同一份範例照抄當作獨立實作驗收。Day 01 保留原先已完成的歷史紀錄，新流程自下一堂起套用。
- 筆記的實作重點使用主項目與子條列；每題複習答案必須能從當日實作重點找到，標示對應項目。
- 英文縮寫首次出現補上英文全名與中文說明。每階段驗收若未通過，先修正再前進。
- 技術角色與概念優先使用英文；每日課程第一次出現時使用 `Caller(呼叫端)`、`Executor(執行器)` 等英文搭配中文格式，後續直接使用英文。英文縮寫仍於首次出現補上英文全名與中文說明。依實際角色選詞，區分 Caller 與 SSH Client，避免混淆。
- 教學以逐段對話進行：每次聚焦一個觀念，搭配 sample code（範例程式碼）說明資料與控制流程，帶學員走查並回應提問後再往下。不將一次貼完教學摘要視為教學完成；純設計課也可用最小模擬程式輔助理解，不提前實作後續完整功能。確認教學走查完成後才進入正式三題複習。
- 結課心得須記錄學員當日較不熟悉的觀念、原先理解、釐清內容與仍待加強之處；根據實際回答記錄，不把一次補答正確視為已完全熟練。
- Code Review 採資深工程師的設計角度，在題目範圍內主動檢查契約與文件是否明確、資源所有權、狀態模型、責任邊界、輸入與邊界行為、例外及清理失敗的處理、診斷資訊和測試有效性。即使測試全部通過，也須提出實際存在的模糊定義或設計缺口，不等學員追問才揭露。說明具體情境、影響、程式位置與適度的改善方向；區分必須修正、非阻擋改善與超出本課的延伸議題。不為形式增加抽象或功能，不因尚未教到的延伸功能否定當日驗收；評分明確標示評估標準與驗證限制。
- 以現有 Windows、16GB 記憶體與單台 Ubuntu 虛擬機完成；先用假物件模擬多目標，需要時再用同一台 Ubuntu 測試多工作，避免額外虛擬機負擔。

## Phase 1：Remote Command Executor（遠端指令執行器）｜第 1–15 天

階段成果：可同步執行單一遠端指令，保留完整結果，明確處理失敗、逾時與清理。

- [x] **Day 01｜環境確認與基礎複習**（[教材](Course_Day1.md)）
  - 練習：檢查虛擬環境、套件、pytest 收集、fixture（測試前置與清理機制）與現有程式。
  - 驗收：收集到 1 個測試且不要求密語；能區分身分驗證失敗與指令回傳非零。已完成筆記與三題複習。
- [x] **Day 02｜需求與責任分工**（[教材](Course_Day2.md)）
  - 練習：自行列出輸入、輸出、責任與失敗分類；區分必要功能與後續功能。
  - 驗收：用成功、非零結束代碼、驗證失敗、逾時四種情境走查設計，沒有模糊的回傳約定。
  - 完成紀錄：見 Note_Day2_261031.md；對話教學、三題複習與磁碟檢查獨立設計練習已完成，以設計走查驗收，未執行遠端連線。
- [x] **Day 03｜資料模型設計**（[教材](Course_Day3.md)；[結課筆記](Note_Day3_261102.md)）
  - 練習：設計連線設定與指令結果；討論必要欄位、預設值與不可變資料。
  - 驗收：能表達標準輸出、標準錯誤、結束代碼與耗時；測試有效與無效設定，不把密語暴露在物件顯示文字。
- [x] **Day 04｜模組邊界與可測試性**（[教材](Course_Day4.md)；[結課筆記](Note_Day4_261103.md)）
  - 練習：規劃檔案、函式與依賴注入；設計可替換的連線建立入口。
  - 驗收：匯入新模組不輸入、不連線；假連線可取代真實連線，設計沒有測試專用分支。
- [x] **Day 05｜私鑰與連線生命週期**（[教材](Course_Day5.md)）
  - 完成紀錄：2026-11-09 通過互動終端機真實 SSH 私鑰登入驗收，`hostname` 回傳 `serverlab-ubuntu`。見 [Day 5 筆記](Note_Day5_261104.md)。

  - 驗收：假物件驗證連線參數與關閉行為；於互動終端機完成一次 SSH（Secure Shell，安全遠端連線協定）連線。
- [x] **Day 06｜單一指令成功路徑**（[教材](Course_Day6.md)）

  - 練習：以最小同步流程執行 hostname，組成結果物件。
  - 驗收：Ubuntu 回傳 serverlab-ubuntu、結束代碼 0；對應假連線單元測試通過。
- [x] **Day 07｜非零結果與輸出保真**（[教材](Course_Day7.md)；[結課筆記](Note_Day7_261109.md)）
  - 練習：保留兩條輸出串流及有意義的空白，區分指令失敗與執行器失敗。

  - 練習：定義連線、身分驗證與指令執行相關例外，保留原始原因。
  - 驗收：用假物件觸發各類失敗，呼叫端可區分；錯誤訊息不包含密語。
- [ ] **Day 09｜資源清理與失敗注入**（[教材](Course_Day9.md)）
  - 練習：檢查 try/finally 與 context manager（情境管理器）的取捨。
  - 驗收：連線、執行、讀取各階段拋例外時均嘗試清理；明確決定清理失敗時如何保留主要錯誤。
- [ ] **Day 10｜逾時需求與時間預算**（[教材](Course_Day10.md)）
  - 練習：分開定義連線階段限制與指令總期限，以單調時鐘計算截止時間。
  - 驗收：列出「持續輸出仍不結束」與「完全無輸出」案例；用可控制的時鐘測試期限計算。
- [ ] **Day 11｜持續讀取雙串流**（[教材](Course_Day11.md)）
  - 練習：持續處理 stdout（Standard Output，標準輸出）與 stderr（Standard Error，標準錯誤），避免只等結束代碼。
  - 驗收：假通道交錯產生兩種輸出，皆完整取得；空輸出也能結束，等待迴圈避免忙碌輪詢。
- [ ] **Day 12｜指令總期限實作**（[教材](Course_Day12.md)）
  - 練習：將截止時間套用到執行迴圈，定義逾時例外及部分輸出的處理。
  - 驗收：持續輸出與無輸出兩種長指令都會逾時；清理本機資源，說明不保證遠端子程序全部停止。
- [ ] **Day 13｜邊界案例與輸出上限**（[教材](Course_Day13.md)）
  - 練習：決定解碼錯誤及最大輸出量的政策。
  - 驗收：空輸出、非 ASCII（American Standard Code for Information Interchange，美國資訊交換標準碼）文字、不完整編碼與超限輸出皆有明確且可測試的結果。
- [ ] **Day 14｜單元測試與整合測試分流**（[教材](Course_Day14.md)）
  - 練習：區分無網路單元測試與實際 Ubuntu 整合測試，讓遠端測試需明確選用。
  - 驗收：預設測試不連線、不要求密語；明確選用後才執行真實連線測試，收集階段無副作用。
- [ ] **Day 15｜Phase 1 驗收與重構**（[教材](Course_Day15.md)）
  - 練習：審查責任分工、公開介面、例外與資源生命週期，整理使用方式。
  - 驗收：成功、非零、驗證失敗、連線失敗、逾時、大量雙串流、例外清理均通過；記錄已知限制。

## Phase 2：設定、紀錄與重試｜第 16–25 天

階段成果：執行器可透過終端機操作，具備安全的診斷紀錄與有邊界的重試。

- [ ] **Day 16｜命令列需求與參數設計**（[教材](Course_Day16.md)）
  - 練習：設計 CLI（Command-Line Interface，命令列介面）的主機、指令與逾時參數。
  - 驗收：參數解析單元測試涵蓋缺參數、錯誤數值與說明文字；解析參數不建立連線。
- [ ] **Day 17｜命令列串接與退出狀態**（[教材](Course_Day17.md)）
  - 練習：串接執行器，定義工具本身與遠端指令的狀態對應。
  - 驗收：成功、遠端非零及工具失敗皆有明確輸出；不把密語放入命令列參數。
- [ ] **Day 18｜設定載入與優先順序**（[教材](Course_Day18.md)）
  - 練習：選擇一種標準函式庫支援的設定檔格式，定義預設值與命令列覆寫規則。
  - 驗收：有效設定、格式錯誤、缺欄位與覆寫規則測試通過；範例設定不含憑證。
- [ ] **Day 19｜Logging（事件紀錄）基礎**（[教材](Course_Day19.md)）
  - 練習：規劃紀錄層級、工作識別碼、開始與結束事件。
  - 驗收：測試可捕捉成功與失敗紀錄，辨識同一工作；函式庫不擅自重複配置全域輸出。
- [ ] **Day 20｜敏感資料與診斷品質**（[教材](Course_Day20.md)）
  - 練習：審查例外、設定顯示與紀錄；明確決定是否記錄指令及其輸出。
  - 驗收：以假密語作為測試資料，確認不出現在紀錄；預設不把任意遠端輸出寫入紀錄。
- [ ] **Day 21｜Retry（重試）需求分析**（[教材](Course_Day21.md)）
  - 練習：分類可重試的暫時故障，討論重複執行副作用與冪等性。
  - 驗收：建立失敗決策表；驗證失敗與可能已啟動的非冪等指令不盲目重試。
- [ ] **Day 22｜有限次數重試**（[教材](Course_Day22.md)）
  - 練習：加入嘗試次數與等待策略，注入可替換的等待函式。
  - 驗收：第一次失敗後成功、持續失敗、不可重試三種案例通過，測試不需真實長時間等待。
- [ ] **Day 23｜退避與重試總預算**（[教材](Course_Day23.md)）
  - 練習：加入退避、等待上限與剩餘時間檢查，討論隨機抖動。
  - 驗收：沒有超出允許的嘗試次數與時間預算；時間耗盡不再發出新連線。
- [ ] **Day 24｜測試替身與行為驗證**（[教材](Course_Day24.md)）
  - 練習：整理假時鐘、假連線與故障情境，移除脆弱的實作細節斷言。
  - 驗收：測試驗證公開行為，失敗訊息可理解；不依賴本機時間、Ubuntu 或測試順序。
- [ ] **Day 25｜Phase 2 驗收**（[教材](Course_Day25.md)）
  - 練習：從命令列完成設定載入、執行、診斷與安全重試的完整流程。
  - 驗收：錯誤設定快速失敗、紀錄可追蹤、重試有上限；完成審查與操作文件。

## Phase 3：Concurrency（並行處理）、Worker Pool（工作者集區）與 Queue（佇列）｜第 26–38 天

階段成果：可限制同時執行量，接收一批工作並可靠收尾。

- [ ] **Day 26｜並行需求與工作模型**（[教材](Course_Day26.md)）
  - 練習：比較循序、執行緒與程序，定義工作識別碼、輸入順序與完成順序。
  - 驗收：選擇適合網路等待的方式；用三個不同耗時工作說明預期結果。
- [ ] **Day 27｜同步批次基準**（[教材](Course_Day27.md)）
  - 練習：先建立循序批次執行介面，保留每項結果與失敗。
  - 驗收：空批次、混合成功失敗、重複工作皆可識別；單項失敗不丟失其他結果。
- [ ] **Day 28｜最小工作者集區**（[教材](Course_Day28.md)）
  - 練習：使用標準函式庫 ThreadPoolExecutor，設定最大工作者數量。
  - 驗收：以同步事件與計數器確認實際並行上限，不單靠睡眠秒數判定正確性。
- [ ] **Day 29｜並行例外與結果收集**（[教材](Course_Day29.md)）
  - 練習：逐項收集完成結果與例外，維持工作識別關係。
  - 驗收：部分工作拋例外時其他工作仍可完成，所有提交工作都有可說明的結果。
- [ ] **Day 30｜連線所有權與執行緒安全**（[教材](Course_Day30.md)）
  - 練習：每項工作管理自己的連線，檢查共享可變資料與紀錄資訊。
  - 驗收：並行工作不共用同一 SSHClient；假連線測試確認各自建立與清理。
- [ ] **Day 31｜佇列與背壓設計**（[教材](Course_Day31.md)）
  - 練習：區分輸入佇列、執行中工作與結果，定義容量滿時的阻擋或拒絕政策。
  - 驗收：用工作者忙碌且佇列已滿的情境走查，明確區分提交等待與指令執行期限。
- [ ] **Day 32｜有界提交實作**（[教材](Course_Day32.md)）
  - 練習：在既有集區外加入有界輸入佇列與受控派送，避免一次提交全部工作。
  - 驗收：輸入量超過容量時依政策處理，等待中的工作與執行中工作皆有上限。
- [ ] **Day 33｜佇列例外與工作計數**（[教材](Course_Day33.md)）
  - 練習：保證取出的項目即使失敗也完成佇列計數，避免 join 永遠等待。
  - 驗收：工作失敗、空佇列與派送結束都能收尾，不遺漏完成通知。
- [ ] **Day 34｜批次期限與取消語意**（[教材](Course_Day34.md)）
  - 練習：分清楚尚未啟動與正在執行的工作，設計合作式停止訊號。
  - 驗收：未啟動工作可取消；執行中工作於檢查點或既定期限退出，不宣稱可強制終止執行緒。
- [ ] **Day 35｜正常關閉與中斷**（[教材](Course_Day35.md)）
  - 練習：停止接收、處理待執行工作政策、等待工作者與關閉資源。
  - 驗收：正常結束與使用者中斷皆可在已定義的期限內收尾，紀錄未完成工作。
- [ ] **Day 36｜競態條件測試**（[教材](Course_Day36.md)）
  - 練習：使用事件與屏障控制交錯順序，檢查關閉和提交同時發生的情境。
  - 驗收：能穩定重現至少一個交錯情境；沒有重複結果、遺失工作或越過容量限制。
- [ ] **Day 37｜單台 Ubuntu 並行整合**（[教材](Course_Day37.md)）
  - 練習：以低工作者數執行安全、有限時間的多項遠端工作。
  - 驗收：工作識別與輸出不混淆，含非零及逾時案例；所有本機連線完成清理。
- [ ] **Day 38｜Phase 3 驗收**（[教材](Course_Day38.md)）
  - 練習：整體審查佇列、集區、取消、期限與資源所有權。
  - 驗收：有界容量、混合失敗與關閉案例全部通過；文件描述順序與取消限制。

## Phase 4：SQLite（嵌入式關聯式資料庫）與執行紀錄｜第 39–47 天

階段成果：執行歷史可儲存與查詢，資料庫錯誤可辨識，並行寫入有清楚的所有權。

- [ ] **Day 39｜歷史資料需求與結構**（[教材](Course_Day39.md)）
  - 練習：設計執行批次、工作與嘗試紀錄，區分執行結果與儲存結果。
  - 驗收：成功、重試後成功、逾時、取消皆有明確欄位；資料表不保存密語。
- [ ] **Day 40｜資料存取邊界**（[教材](Course_Day40.md)）
  - 練習：以 Python sqlite3 建立資料表與資料存取介面。
  - 驗收：使用臨時資料庫測試新增與查詢；值透過參數綁定，連線生命週期明確。
- [ ] **Day 41｜交易與失敗回復**（[教材](Course_Day41.md)）
  - 練習：界定一次寫入的交易範圍，處理部分失敗。
  - 驗收：故障注入後不留下半套關聯資料；提交與回復行為可驗證。
- [ ] **Day 42｜並行結果集中寫入**（[教材](Course_Day42.md)）
  - 練習：讓專責寫入者擁有資料庫連線，工作者經由有界結果佇列交付資料。
  - 驗收：多工作者結果完整寫入，不跨執行緒共用不合適的連線；寫入者失敗能通知上游。
- [ ] **Day 43｜查詢與資料保留**（[教材](Course_Day43.md)）
  - 練習：加入依批次、狀態查詢與有限筆數輸出，定義輸出保存上限。
  - 驗收：空資料、混合狀態與筆數限制測試通過，查詢不載入全部歷史至記憶體。
- [ ] **Day 44｜中斷後的狀態辨識**（[教材](Course_Day44.md)）
  - 練習：處理程序異常結束留下的執行中紀錄，區分未知結果與可安全重跑。
  - 驗收：模擬重啟後可辨識未完成工作，不自動重跑可能有副作用的指令。
- [ ] **Day 45｜紀錄匯出**（[教材](Course_Day45.md)）
  - 練習：匯出 JSON（JavaScript Object Notation，JavaScript 物件表示法）格式的有限批次報告。
  - 驗收：中文、換行、特殊字元與失敗資料可往返解析；報告不含憑證。
- [ ] **Day 46｜儲存故障與關閉順序**（[教材](Course_Day46.md)）
  - 練習：模擬資料庫鎖定、寫入例外與關閉時仍有結果待寫入。
  - 驗收：不永久等待、不默默遺失結果；區分遠端執行成功但結果儲存失敗。
- [ ] **Day 47｜Phase 4 驗收**（[教材](Course_Day47.md)）
  - 練習：完成命令列提交、並行執行、歷史儲存、查詢與匯出。
  - 驗收：混合結果批次端到端通過；檢查交易、清理、敏感資料與重啟狀態。

## Phase 5：Testing（測試）與 Performance Optimization（效能最佳化）｜第 48–54 天

階段成果：以可重現的測量找出瓶頸，完成一項有證據的改善。

- [ ] **Day 48｜風險導向測試盤點**（[教材](Course_Day48.md)）
  - 練習：把需求對應到既有測試，找出關閉、逾時、失敗傳遞等缺口。
  - 驗收：產出需求與測試對照，補上最高風險缺口，不以測試數量作為品質指標。
- [ ] **Day 49｜可重現的效能基準**（[教材](Course_Day49.md)）
  - 練習：定義工作負載、總耗時、吞吐量、等待與執行時間，分開假環境與真實 SSH 測量。
  - 驗收：固定條件重複測量並記錄環境與波動；不以單次測量下結論。
- [ ] **Day 50｜並行度實驗**（[教材](Course_Day50.md)）
  - 練習：比較 1、2、4 個工作者，在現有記憶體與 Ubuntu 資源內觀察變化。
  - 驗收：記錄耗時、失敗與資源觀察，說明為何增加工作者不保證等比例加速。
- [ ] **Day 51｜瓶頸分析**（[教材](Course_Day51.md)）
  - 練習：使用標準函式庫分析本機耗時，區分遠端等待、連線成本、輪詢與資料寫入。
  - 驗收：提出一項由測量支持的瓶頸假說，不將本機分析直接當作遠端程式內部分析。
- [ ] **Day 52｜實作一項效能改善**（[教材](Course_Day52.md)）
  - 練習：依證據選擇改善輪詢、寫入批次或其他瓶頸，維持原本行為契約。
  - 驗收：相關正確性測試通過，使用相同負載比較改善前後；無改善時如實記錄並檢討。
- [ ] **Day 53｜有限壓力與資源觀察**（[教材](Course_Day53.md)）
  - 練習：執行有限批次，觀察佇列容量、輸出上限、連線清理與記憶體趨勢。
  - 驗收：沒有隨工作總數無界成長的待處理資料；測試有停止條件，不耗盡家用主機資源。
- [ ] **Day 54｜Phase 5 驗收與效能報告**（[教材](Course_Day54.md)）
  - 練習：整理方法、數據、限制與改善取捨。
  - 驗收：他人可依步驟重現實驗；結果同時呈現效能與正確性，避免宣稱超出證據的成效。

## Phase 6：CI（Continuous Integration，持續整合）與求職作品交付｜第 55–60 天

階段成果：可安裝、可自動測試、可說明設計取捨的作品。

- [ ] **Day 55｜安裝與相依套件重現**（[教材](Course_Day55.md)）
  - 練習：整理 pyproject.toml、支援版本與套件版本重現方式。
  - 驗收：乾淨虛擬環境可依文件安裝並執行命令列說明；沒有依賴開發機的絕對路徑。
- [ ] **Day 56｜持續整合流程**（[教材](Course_Day56.md)）
  - 練習：依當時平台免費方案與可用帳號選擇服務，建立無 Ubuntu 依賴的自動測試流程。
  - 驗收：流程執行單元測試且不要求密語、不連家中主機；缺少遠端帳號或權限時記錄尚未完成的實際運行驗證。
- [ ] **Day 57｜跨平台與品質檢查**（[教材](Course_Day57.md)）
  - 練習：檢查 Windows 與 Linux 的路徑、編碼及時間行為，加入一項有價值的靜態檢查。

- [ ] **Day 58｜操作文件與架構說明**（[教材](Course_Day58.md)）
  - 練習：補齊安裝、範例、架構圖、測試分流、逾時、取消、重試與憑證限制。
  - 驗收：依文件從乾淨環境完成最小操作；文件沒有私鑰、密語或依賴未說明的步驟。
- [ ] **Day 59｜展示與設計問答**（[教材](Course_Day59.md)）
  - 練習：準備約 5 分鐘展示，說明一次失敗處理、一次並行取捨與一次效能改善。

- [ ] **Day 60｜最終驗收與後續路線**（[教材](Course_Day60.md)）
  - 練習：完整執行驗收清單、審查已知問題、整理版本與下一階段待辦。
  - 驗收：安裝、單元測試、選用整合測試、混合批次、逾時、取消、儲存與匯出可展示；整理殘留風險。提交或發布遠端版本依當時明確授權執行。
